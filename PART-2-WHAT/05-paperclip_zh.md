# 第五章：Paperclip

> "我们塑造工具，然后工具塑造我们。"
> — 约翰·卡尔金 (John Culkin)

现有数千种 AI 工具、数百个 Agent 框架、数十个工作流平台。**Paperclip 都不是**。

**Paperclip 让你能够：**
- **雇佣 AI Agent**，分配职位头衔。
- **放入组织架构图**。
- **分配任务并保留完整对话线程**。
- **设置月度预算**（硬性支出限制）。
- **重大决策需人工审批**。
- **所有操作记录在永久审计日志中**。

它不帮你"使用 AI"，而是帮你**像运营公司一样运行 AI**。因为你正在构建的正是这样一家公司。

如果山姆·阿尔特曼所说的"一人独角兽公司"真的存在（前文数据表明它必将到来），它将运行在类似 Paperclip 的系统上。**不是聊天机器人，不是工作流，而是 AI 公司的操作系统**。

## 它不是什么：非聊天、非框架、非工作流

先说"不是什么"，这很重要。大多数人会将 Paperclip 套入已知的工具类别——但**每个类比都是错的**。

| ❌ 错误归类 | ✅ Paperclip 真相 |
|------------|------------------|
| **不是聊天机器人**：没有问答界面。它不与你对话，而是编排任务。 | 它是组织者，不是聊天伙伴。 |
| **不是 Agent 框架**（如 LangChain, CrewAI）：不帮你*构建* Agent。 | 它管理任何已建的 Agent（Claude Code, Cursor, HTTP Agent, Bash 脚本等）。 |
| **不是工作流构建器**（如 Zapier）：不链式执行"当 A 发生则做 B"。 | 它建模**组织层级**，支持授权、决策上下流动（像餐厅而非食谱）。 |
| **不是提示词管理器**：不存储或优化提示。 | 它管理*Agent*（持久实体，含角色、预算、权限、历史）。 |

停止与其他工具比较，Paperclip 的本质就清晰了：**将 AI Agent 作为员工运行的组织基础设施**。不多不少。

## 像公司一样编排 Agent

Paperclip 基于一个核心洞察：**如果你想让 AI Agent 承担公司的全部工作，就必须像公司一样组织它们**。

### 🏢 1. 组织架构图 (Org Charts)
- **每个 Agent 都有明确职位**：角色、汇报线、层级。
- 示例：内容写手 → 编辑总监 → 市场负责人。
- **决定任务如何分配、决策如何升级、谁拥有何种权限**。

### 🎯 2. 目标级联 (Goal Cascading)
- **公司目标沿层级向下流动**。
- 示例：本月发布 20 篇文章 → 市场负责人拆解为编辑任务 → 总监分配给写手 → 进度向上汇总。
- **从使命到执行的对齐**。

### 🏭 3. 多公司支持 (Multiple Companies)
- **从 Paperclip 实例运行多家独立公司**，数据完全隔离。
- 示例：内容公司 + 电商运营 + 咨询公司 → 各自独立的 Agent、预算和治理。

这听起来显而易见，但**几乎没有任何 AI 工具这样思考**。大多数围绕任务、提示或工作流构建，而非组织。Paperclip 的赌注是：**组织结构本身就是产品**——它将 AI Agent 集合转化为可运营的企业。

## 心跳、预算与紧急开关 (Heartbeats, Budgets, Kill Switches)

### ⏰ 1. 定时工作（无需人工干预）
Paperclip Agent 按**心跳 (Heartbeats)** 调度自动唤醒：
- **内容写手**：每日检查编辑日历。
- **SEO Agent**：每周优化已发布内容。
- **研究 Agent**：每月产出竞品分析。

这就是"喝咖啡时检查仪表盘"成为现实的原因：**工作按时间表发生，而非按命令触发**。

### 📝 2. 每项任务全程记录
- **每个工件都是带完整对话线程的任务**。
- Agent 执行时，其推理链、行动和决策被记录。
- **若 A 委托给 B，线程延续**；你若介入，可追溯"发生了什么、顺序如何、为何如此"。

在传统公司中，你往往无法知道员工如何得出结论。**Paperclip 默认记录每一步**。

### 💰 3. 硬性支出上限 (Hard Caps)
**这是 Paperclip 区别于一切其他工具的核心**。
- **每个 Agent 有月度预算**（API 调用和计算费用的硬性上限）。
- **80% → 警告**。
- **100% → Agent 暂停**（无例外、无超支）。

你可跨 Agent/任务/项目/公司追踪成本，**清楚每一分钱去向**。尝试在人类员工身上获得这种可见性？

### 🚦 4. 人工审批闸门 (Approval Gates)
并非所有事情都应自动运行。Paperclip 通过**审批检查点**处理：某些行动需你签字才能继续。
- **每封对外邮件都审批？** → 设闸门。
- **发布前审查内容？** → 设闸门。
- **控制新 Agent 招聘或战略调整？** → 董事会级审批。

这是**治理，而非官僚主义**。你决定哪些受控、哪些自由运行。**系统强制执行**。

### 🔒 5. 永久审计日志 (Permanent Audit Trail)
- **每个决策、工具调用、完成任务 → 记录且不可篡改**。
- 你无法修改日志，Agent 也无法。发生的事永远留存记录。

这赋予大多数人类员工公司缺乏的东西：**完美问责制**。
- **输出错误？** → 追溯哪步出错、输入是什么。
- **输出优秀？** → 复现成功模式。

### 🛑 6. 随时完全接管 (Full Override)
有时你需要"拉闸"。Paperclip 允许你：
- **终止任何 Agent**。
- **覆盖任何任务**。
- **在任何点介入**。

Agent 自主工作，但**你持有紧急停止开关 (Kill Switch)**。
这不仅在实践中重要，在心理上同样关键：**知道你有完全控制权，才敢放手让 Agent 运行**。你不是交出钥匙，而是**带监督地授权**。

## 支持任意运行时 (Bring Whatever Runtime You Want)

Paperclip 最明智的决策之一：**不关心 Agent 如何构建**。它管理组织层（角色、任务、预算、治理），将智能交给任何你偏好的运行时：

- **Claude Code**（开发）
- **自定义 HTTP Agent**（专项功能）
- **Bash 脚本**（常规自动化）
- **混合搭配整个组织架构图**

随着模型和运行时改进，你的 Paperclip 公司也随之进化。**不锁定单一供应商**，而是构建可随时接入最佳智能的组织结构。

两年后 AI 格局将大不相同。**角色、层级、预算、治理**是管理概念，而非技术赌注——它们不会过时。

## 免费开源，一键安装 (Free, Open-Source, One Command)

Paperclip 采用 **MIT 许可证**，完全开源：
- 可阅读每一行代码。
- **无账户、无订阅、无使用费**。
- 在本地运行，内置 Postgres 数据库。

**安装命令**:
```bash
npx paperclipai onboard --yes
```

从零到运行 AI 公司基础设施，只需几分钟。第七章将带你一起完成。

**免费开源的意义超越成本**：无供应商锁定、无价格突变风险、不依赖可能转型或倒闭的公司。**你的基础设施属于你自己**。

## Cliphub：将公司模板作为产品 (Company Templates as Products)

Paperclip 已宣布 **Cliphub**（正在开发中）：预建公司模板市场。
- 无需从头设计 AI 公司，直接下载模板（内容公司、电商运营、咨询公司）。
- **已配置好 Agent、角色、预算和工作流**。

像浏览 App Store 一样使用 Cliphub，但下载的是**公司结构**：
- "5 Agent 内容机构 → 安装并定制"。
- "电商运营团队 → 接入产品即开即用"。
- "客服部门 →24 小时处理工单"。

Cliphub 尚未上线，但愿景明确：**启动 AI 公司像安装模板一样简单**。如果你想成为**创建并销售这些模板的人**，窗口期现已打开。

## 平台时刻 (Platform Moments)

每次重大经济变革都有其"平台"：
- **工业革命** → 工厂。
- **计算机时代** → 办公室。
- **互联网** → 浏览器。
- **移动时代** → App Store。

AI 时代的平台是什么？

不一定是 Paperclip（尽管它是当前最强候选），而是它所代表的概念：**以结构化方式组织、管理和治理 AI Agent 作为公司**。

有人将构建面向原生 AI 企业的标准基础设施。**现在基于该基础设施建设的创始人，等同于 1996 年构建互联网或 2008 年构建 App Store 的人**。
