# 第七章：打开你的终端

> "开始的最佳方式，就是停止空谈，立即行动。"
> — 沃尔特·迪士尼 (Walt Disney)

**关闭其他标签页。打开终端。**
30 分钟后，你将拥有第一家正在运行的 AI 公司。

不是演示 demo，不是思想实验。**真实运行**：有 Agent、任务、以及可实时监控的仪表盘。

## 你需要什么？
只需两样东西：

### 1. Node.js (版本 18 或更高)
检查是否已安装：
```bash
node --version
```
- 看到 `v18`, `v20` 或更高 → **继续**。
- 看到其他版本或未安装 → 从 [nodejs.org](https://nodejs.org) 下载最新 LTS 版本（约 2 分钟）。

### 2. 一个终端
- **macOS**: Terminal 或 iTerm2。
- **Windows**: PowerShell 或 Windows Terminal。
- **Linux**: 你正在使用的任何终端。

**只要能输入命令并按回车，就具备本章所需的所有技能。**
- ❌ 不需要 Docker。
- ❌ 不需要云账户。
- ❌ 不需要 API Key。
- ❌ 不需要信用卡。

---

## Step 1: 安装 Paperclip

```bash
npx paperclipai onboard --yes
```

**一条命令，完成所有工作**：
- 下载 Paperclip。
- 设置内置 Postgres 数据库。
- 创建目录结构。
- 启动平台。

`--yes` 标志接受默认配置，非常适合首次运行。
**安装耗时**: 1-3 分钟（取决于网络）。

完成后，你会看到一个本地 URL（通常是 `http://localhost:3000`）。
**打开它 → 这就是你的 Paperclip 仪表盘，也就是 AI 公司的操作系统。**

---

## Step 2: 给你的公司命名
仪表盘会提示你创建一家公司。三个字段至关重要：

| 字段 | 建议 |
|------|------|
| **Name (名称)** | 选一个真实的名字。"Acme Content" 可以，但 "Adams Media Group" 更好。**当你把它印在名片上时，你会更认真地对待它**。 |
| **Description (描述)** | 1-2 句话。*"为个人理财领域生产 SEO 优化的博客内容"* 优于 *"测试 AI 功能"*。**具体性决定了你如何设计 Agent 和分配工作**。 |
| **Goals (目标)** | 公司存在的目的是什么？<br>• "每周发布 4 篇高质量博客"<br>• "2 小时内处理并回复客户咨询"<br>**目标会向下级联到 Agent**。确保具体且可衡量。 |

点击 **Create** → 你的公司现在有了仪表盘、任务板、预算追踪器和一张空的组织架构图。
**时间到：雇佣你的第一个员工。**

---

## Step 3: 雇佣一个 Agent
导航到 **Agents** → **Create New**。

### 📝 Name & Role (名称与角色)
- 给 Agent 起个名字和头衔。
  - "Alex, Content Writer"（内容写手）
  - "Morgan, Research Analyst"（研究分析师）
- **名字只是装饰，角色描述才重要**。像写招聘启事一样：
  > "撰写关于个人理财主题的 1000-1500 字博客文章。遵循 SEO 最佳实践，为普通成年读者产出清晰、引人入胜的文字。"

### ⚙️ Runtime (运行时)
告诉 Paperclip 构建哪种类型的 Agent：
- **Claude Code**（如果你用 Claude）→ 选择此运行时。
- **自定义 API** → 配置 HTTP Agent。
- **最简单选项** → Bash 脚本 Agent（用于基础自动化任务）。

*运行时之后可更改。选一个继续即可。*

### 💰 Budget (预算)
设置月度上限。**$50** 足够实验且无需担心。

### ⏰ Heartbeat (心跳/调度频率)
Agent 多久检查一次工作？
- **内容写手** → 每日。
- **客服 Agent** → 每小时。
- **周报生成器** → 每周。

**匹配工作节奏与调度频率。**

点击 **Create** → 你的第一个员工已入职。
- ❌ 无需面试。
- ❌ 无需录用函。
- ❌ 无需提前两周通知离职。

---

## Step 4: 分配任务
导航到 **Task Board** → **Create Task** → 指派给你的 Agent。

### 🎯 保持第一个任务简单且具体：
| 公司类型 | 示例任务提示词 (Brief) |
|---------|----------------------|
| **内容公司** | "撰写一篇 1200 字的博客，主题为'自由职业者前 5 大预算策略'。包含引言、五个明确定义的策略（附解释）和结论。针对关键词 'budgeting tips for freelancers' 进行优化。" |
| **研究公司** | "编译针对小型团队的前 5 大项目管理工具的竞品分析。对每个工具，包含定价、核心功能、优缺点和目标用户。以结构化格式呈现。" |
| **电商公司** | "为以下 10 件商品撰写产品描述 [列出物品]。每个描述 100-150 字，突出核心优势并包含明确的行动号召。" |

**注意具体性**。AI Agent 像人类员工一样，清晰的简报才能产出好结果。
- ❌ "写点关于预算的内容" → 模糊无用。
- ✅ 上述简报 → 可直接发布的质量。

**提交任务**。如果心跳时间到，Agent 会自动接手；否则可手动触发运行。

**观察任务线程**。思考链的每一步都记录在对话中——这就是第五章提到的"透明度"的实际体现。

---

## Step 5: 阅读线程，而不仅仅是结果
当 Agent 完成任务时，**克制直接跳转到交付物的冲动**。研究任务线程——那是你学习的地方。

### 🔍 在**线程 (Thread)** 中寻找：
- Agent 如何理解你的简报？
- 它采取了哪些步骤？
- 有哪些你未预期的决策？
- 任务消耗了多少预算？

### 📊 在**输出 (Output)** 中问：
- 你会发布它、发给客户或据此行动吗？
- 哪里不足？**"不够好"** 毫无帮助，要具体。
- 下次你会如何修改简报？

**这个任务既产出了工作，也校准了你的期望**。你在了解 Agent 的能力、推理方式和最佳指令模式。后续每个任务都会因此更精准。

## 与仪表盘的五分钟探索
现在你有：公司、Agent、已完成的任务。开始探索吧！

| 模块 | 功能说明 |
|------|---------|
| **Company Overview (公司概览)** | 名称、描述、目标、高层指标：Agent 数量、活跃任务数、完成任务数、总花费。 |
| **Org Chart (组织架构图)** | 目前只有一个 Agent。随着成长，层级、角色和汇报线将在此显示。 |
| **Task Board (任务板)** | 所有任务：待办、进行中、已完成、阻塞。每个任务附带对话线程、指定 Agent 和状态。**这是你的指挥中心**。 |
| **Budget Tracking (预算追踪)** | 每个 Agent 的支出、月度总计、利用率百分比。<br>🟢 = 健康，🟡 = 接近上限，🔴 = 已暂停。 |
| **Audit Logs (审计日志)** | 不可篡改的完整记录：每个 Agent 行动、决策、工具调用。**想知道"为什么发生？" → 查这里**。 |

---

## ⚠️ 常见卡点与解决方案

| 问题 | 原因/解决方案 |
|------|--------------|
| **"Command not found" (npx 命令未找到)** | Node.js 未安装或未加入 PATH。从 nodejs.org 重新安装，勾选"Add to PATH"选项。 |
| **Port already in use (端口已被占用)** | 其他服务占用了 3000 端口。停止该服务或配置不同端口。 |
| **Agent 忽略新任务** | 检查心跳调度。如果设为"每日"且刚创建任务，Agent 要等到明天才会运行。**手动触发一次**。 |
| **输出质量弱** | 通常是简报问题，而非 Agent 问题。<br>• 让描述更具体<br>• 提供优秀输出示例<br>• 明确长度、格式和语气约束 |
| **预算消耗过快** | 检查模型层级。<br>• Opus 级 → 昂贵<br>• Haiku 级 → 便宜但质量低<br>**推荐 Sonnet 级**：性价比最佳。 |

**大多数人认为这还要等几年，而你刚刚在喝咖啡时就完成了。**

- **今晚之前**：这个 Agent 可按日计划持续产出工作。
- **本周结束前**：3-4 个 Agent 覆盖不同职能。

但**分散的 Agent 运行任务 ≠ 公司**。它们只是沙盒游戏。
**构建真实的公司，意味着像 CEO 一样思考**：定义角色、设计层级、创建授权流程、构建无需你在场即可运行的组织。
