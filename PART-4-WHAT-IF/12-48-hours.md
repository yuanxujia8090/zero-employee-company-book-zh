# 第十二章：前 48 小时行动指南

> "一年后，你会希望今天就开始。"
> — 凯伦·兰布 (Karen Lamb)

你已经了解了**为什么 (Why)**、**是什么 (What)** 和 **怎么做 (How)**。现在，**开始行动**。

本章是你的 **48 小时计划**。不是"下个月"，也不是"某一天"。**就是 48 小时内**。
到本周末结束或度过两个晚上后，你将拥有一家**正在运行并产出真实成果的 AI 公司**。

今天开始的创始人将获得**每日复利的领先优势**。一年后，你会庆幸自己开始了。

---

## 🎯 第一步：选择一个使用场景
**围绕你已经在做的事构建，而非从未尝试过的领域**。最佳的首个使用场景具备三个特质：

| 标准 | 说明与示例 |
|------|-----------|
| **1. 你定期做** | 内容创作、研究、客户沟通、数据分析、报告生成。**任何每周消耗数小时的工作**。 |
| **2. 产出可定义** | 你能描述"好结果"的样子。能写出指定格式、长度、质量标准和成功标准的简报。 |
| **3. 风险可控** | 首个 AI 公司不应处理最重要客户或最高营收产品。**从"出错只需重做"而非"会失去客户"的地方开始**。 |

### ✅ 推荐的首个场景：
- 📝 博客内容生产
- 📱 社交媒体内容
- 🔍 市场研究与竞品分析
- ✉️ 邮件通讯
- 🛒 产品描述撰写
- ❓ 客户 FAQ 与知识库维护
- 📊 数据整理与报告

**只选一个**。围绕它构建一家小型、专注的 AI 公司。

---

## 📅 Day 1: 构建 (Build)

### ⏰ 小时 1-2：安装与创建
1. **打开终端**。
2. 运行 `npx paperclipai onboard --yes`。
3. 等待设置完成（2-3 分钟）。
4. **在浏览器中打开仪表盘**。
5. **创建你的第一家 AI 公司**：
   - 起一个真实的名字。
   - 用一句话描述它做什么。
   - 设定第一个月的一个可衡量目标。

**现在你已拥有一家 AI 公司**。它是空的，但它存在。**时间到：雇佣员工**。

---

### ⏰ 小时 2-3: 三个 Agent
根据你的使用场景，创建三个 Agent。以下是通用模式（请适配你的需求）：

| Agent 角色 | 职责说明 |
|-----------|---------|
| **Agent 1: The Doer (执行者)** | 产出的核心结果。<br>• 内容公司 → 写手<br>• 研究公司 → 分析师<br>**精确定义角色**：产出什么、格式如何、标准是什么。 |
| **Agent 2: The Checker (检查者)** | 审查执行者的输出。<br>• 内容 → 编辑<br>• 研究 → 事实核查员<br>• 技术工作 → QA Agent<br>**职责**：发现错误、提升质量、标记需人工审查的内容。 |
| **Agent 3: The Coordinator (协调者)** | 管理工作流：调度任务、追踪截止日期、汇报状态。<br>• 小型操作 → 简单调度器<br>• 大型操作 → 项目经理（负责授权与跟进） |

**为每个 Agent 设置**:
- **具体角色描述**（参考第八章）。
- **月度预算**：起步 $50-$100/个。
- **心跳频率**：每日检查任务。
- **组织架构图位置**：你 → 协调者 → (执行者 + 检查者)。

---

### ⏰ 小时 3-5: 真实工作，非测试任务
**分配真实的工作**。本周你实际会做、且产出可与你的常规工作对比的任务。

**给每个 Agent 分配一个任务**:
- **执行者**：真实任务（如真实文章主题、真实研究问题、真实产品描述列表）。
- **检查者**：审查执行者的输出。
- **协调者**：管理本周的日程安排。

### 📝 撰写具体简报 (Brief)，包含:
- **输出应呈现的形态**。
- **长度或范围要求**。
- **质量标准与约束条件**。
- **风格指南或参考材料**。
- **"完成"的定义**。

**提交任务并观察第一个执行过程**。阅读任务线程（Task Thread）——这是当天最重要的学习时刻。**你在实时观察 Agent 如何解读指令并产出结果**。

---

### ⏰ 小时 5-6: 审查 → 优化
当第一个任务完成后，**审查它**:

| 问题 | 说明 |
|------|------|
| **可用吗？** | 能发布、发给客户或直接行动吗？ |
| **哪里超出预期？** | 通常至少有一方面表现更好。 |
| **哪里不足？** | 通常也存在短板。 |
| **你会如何修改简报？** | **最重要的问题**。不要手动修复输出，而是**优化角色定义或任务简报并重新分配**。你在训练系统，而非亲自干活。 |

---

## 📅 Day 2: 运营 (Operate)

### ☀️ 上午：隔夜产出
如果 Agent 按心跳调度在夜间运行，醒来时会有已完成的任务。检查仪表盘：

- **产出了什么？**
- **是否有预算警告触发？**
- **是否有任何审批闸门被激活？**
- **审计日志显示了什么？**

**审查输出**:
- 对优秀成果：记录原因（是什么让简报有效？）。
- 对薄弱成果：调整角色定义或简报并重新分配。

**这个晨间审查将成为你作为零员工创始人的日常惯例**。耗时约 30-60 分钟。

---

### 🕛 中午：治理设置
在亲眼看到 Agent 工作后，**基于经验而非猜测建立治理**:

| 设置项 | 行动指南 |
|--------|---------|
| **审批闸门** | 基于昨天的输出，哪些内容需要在最终定稿前审查？立即设置这些闸门。 |
| **预算调整** | 初始预算是否过高或过低？根据第一天的实际支出调整。 |
| **质量标准** | 现在看到了 Agent 的产出，编写具体标准并注入角色定义。<br>例："文章必须包含至少三个小标题、引用至少一个数据点，并以明确的行动号召结尾。" |
| **升级规则** | 定义什么情况下需升级给你？<br>• 输出低于质量阈值<br>• 任务延迟<br>• Agent 标记不确定性 |

---

### 🌤️ 下午：排定一周工作
基于过去 24 小时，**分配一整周的任务**。在适当位置设置重复性任务。配置调度器，让工作按适合你生活的节奏从执行者 → 检查者 → 你的审查队列流动。

**此时，你的 AI 公司从实验转变为运营**。你不再测试，而是在运行系统。

---

### 🌙 晚上：五个反思问题
花 30 分钟回答以下问题（**写下答案**）：

1. **今天什么让我感到意外？**
2. **哪些表现超出预期？**
3. **需要调整什么？**
4. **我是否把时间花在了正确的事情上，还是在微观管理？**
5. **如果下周增加第四个 Agent，哪个角色最重要？**

**这些反思将成为让公司持续改进的制度性知识**。

---

## 📆 第一周之后 (The Week After)

| 时间 | 行动指南 |
|------|---------|
| **第 3-5 天** | **运行系统**。执行晨间审查。对简报和角色定义进行增量调整。**克制重新设计的冲动**，让系统运行并从其表现中学习。 |
| **第 6 天：审计** | 审查整周日志。<br>• 计算实际成本 vs. 预算<br>• 评估全周产出质量<br>• 识别模式：什么持续优秀？什么持续薄弱？ |
| **第 7 天：规划** | 基于数据决定：<br>• 继续优化三个 Agent？<br>• 增加第四个角色？<br>• 调整结构或治理规则？ |

**第一周结束时，你对运营 AI 公司的实践经验将超过绝大多数谈论它的人**。

## 🌐 Singularity Playground (社区)
你不必独自摸索。

**Singularity Playground** 是一个由创始人和构建者组成的社区，他们：
- 实验原生 AI 商业模式。
- 分享成功经验。
- 在卡住时提问。
- 推动彼此构建两年前不可能的事物。

### 🎁 你能找到:
- **各阶段的创始人**：从第一天使用 Paperclip 到运营多公司组合。
- **真实案例**：什么有效、什么失败。
- **深度讨论**：治理、Agent 协调与扩展。
- **同行理解**：他们也在构建同样的东西，因此真正懂你在做什么。

零员工公司是一种新的工作方式。**实践者社区将孤独的实验转变为运动**。运动的构建速度远快于个人。

**来打个招呼吧**。分享你前 48 小时构建的东西，提出本书未回答的问题。Singularity Playground 是让这些想法成为**活生生的实践**的地方。
